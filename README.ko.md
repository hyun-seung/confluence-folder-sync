# Confluence Folder Sync

[English](README.md) · 한국어 · [개발 로드맵](ROADMAP.ko.md)

PC의 Obsidian 보관함과 Confluence Cloud를 연결하는 데스크톱 플러그인입니다. 지정한 로컬 폴더를 Confluence 폴더 아래에 발행하고, Confluence의 변경을 비교하거나 새 페이지와 첨부파일을 Markdown 사본으로 내려받습니다. Obsidian에서 직접 처리하므로 별도 서버, 유료 플러그인, 외부 명령어나 Python 실행 환경이 필요하지 않습니다.

[GitHub](https://github.com/hyun-seung/confluence-folder-sync)에서 소스와 개발 이력을 확인할 수 있으며 [MIT 라이선스](LICENSE)로 배포합니다. 2026-11-26 [공식 Obsidian 커뮤니티](https://community.obsidian.md/plugins/confluence-folder-sync)에 등록 요청과 공개 처리를 완료했습니다. 현재 자동 검토 결과와 설치 가능 여부는 해당 페이지에서 확인하세요.

## 설치

1. [Releases](https://github.com/hyun-seung/confluence-folder-sync/releases)에서 최신 릴리스을 엽니다.
2. [confluence-folder-sync-0.7.0.zip](https://github.com/hyun-seung/confluence-folder-sync/releases/download/0.7.0/confluence-folder-sync-0.7.0.zip)을 내려받고 압축을 풉니다. 안에 있는 `confluence-folder-sync` 폴더를 보관함의 `.obsidian/plugins/`에 넣습니다. macOS Finder에서는 `Command + Shift + .`으로 숨김 폴더를 표시할 수 있습니다.
3. 최종 경로가 `.obsidian/plugins/confluence-folder-sync/main.js`인지 확인합니다. 같은 폴더에 `manifest.json`과 `styles.css`도 있어야 합니다. ZIP 대신 릴리스의 개별 파일 3개를 직접 내려받아 같은 경로에 넣어도 됩니다.
4. Obsidian의 **설정 → 커뮤니티 플러그인**에서 **Confluence Folder Sync**를 활성화합니다. Obsidian Desktop 1.14 이상이 필요합니다.

GitHub가 자동 생성한 **Source code (zip)**은 개발용 소스 압축파일이며 폴더 구조가 다릅니다. 수동 설치에는 이름이 `confluence-folder-sync-버전.zip`인 파일을 사용하세요. 한 ZIP에서 한국어와 영어를 모두 지원합니다. 공식 커뮤니티 등록 후에는 Obsidian 안에서 설치하고 업데이트할 수 있게 됩니다.

## 처음 연결하기

처음에는 테스트용 Confluence 폴더와 테스트용 보관함으로 확인하세요.

1. 플러그인 설정의 **Confluence 폴더 URL**에 Confluence 사이드바에서 복사한 폴더 주소를 입력합니다. 일반 페이지 주소와 구분하세요. 예시는 `https://example.atlassian.net/wiki/spaces/DOC/folder/1234`입니다.
2. **Atlassian 이메일**에 토큰을 발급한 계정의 이메일을 입력합니다.
3. [Atlassian API 토큰 설정](https://id.atlassian.com/manage-profile/security/api-tokens)에서 범위 지정 토큰을 만들고, **Confluence API 토큰**의 Obsidian 비밀 선택기를 통해 저장·선택합니다.
4. **발행할 보관함 폴더**와 **가져오기 보관함 폴더**를 보관함 기준 상대 경로로 입력합니다. 두 폴더가 겹치면 안 됩니다. 예를 들어 `Project`와 `Confluence inbox`를 사용합니다.
5. **연결 테스트**를 실행합니다. 왼쪽 리본의 양방향 화살표 버튼이나 명령 팔레트에서 대시보드를 엽니다.
6. 업로드하려면 **발행 허용**을 켭니다. **발행할 문서 검토**에서 문서를 선택하고 **선택한 문서 발행**을 실행한 뒤 확인창에서 대상을 확인합니다.

기본 발행은 사용자가 명령이나 버튼을 실행할 때 작동합니다. 자동 확인과 기존 연결 문서의 자동 발행은 별도로 켤 수 있으며 기본값은 꺼짐입니다. 양쪽 변경을 자동 병합하지 않으며, 변경 없는 문서는 기존 연결 정보를 사용해 건너뜁니다.

## 일상적인 사용 순서

| 목적 | 실행 순서 |
| --- | --- |
| 로컬 수정 발행 | **발행할 문서 검토 → 문서 선택 → 선택한 문서 발행**. 설정에서 발행을 허용하고 확인창의 대상을 확인합니다. |
| Confluence 새 페이지 가져오기 | **변경 사항 미리 보기 → 새 페이지 가져오기**. 사본은 별도 가져오기 폴더에 저장합니다. |
| 현재 버전으로 새 사본 받기 | **전체 사본 내려받기** 또는 페이지 선택 후 **최신 사본 내려받기**. 원본과 이전 사본은 보존합니다. |
| 연결된 원본에 원격 변경 반영 | 일치하는 변경만 고르려면 **로컬 반영 검토**, 전체 해결 본문을 결정하고 원격 기준을 갱신하려면 **본문 충돌 해결**을 사용합니다. |
| 로컬 변경 복구 | **작업 이력 열기 → 백업 열기**. 현재 노트가 기록된 처리 결과와 일치할 때 **백업 복원**을 사용할 수 있습니다. |

먼저 수동 검토로 사용하세요. 자동 확인과 자동 발행은 각각 선택하는 기능이며 기본으로 꺼져 있습니다. 두 자동 모드 모두 원격 변경을 기존 로컬 노트에 자동 반영하지 않습니다.

## 언어 선택

기본값은 **Obsidian 설정 따르기**입니다. Obsidian의 언어가 한국어이면 한국어로, 나머지는 영어로 표시합니다. 플러그인 설정의 **언어 → Obsidian 설정 따르기 / English / 한국어**에서 직접 바꿀 수도 있습니다.

설정, 대시보드, 확인창, 알림, 플러그인에서 정의한 오류 안내와 변경 보고서가 두 언어를 지원합니다. 언어를 바꾸면 명령 팔레트와 리본 안내도 갱신합니다. 노트 본문, Confluence 제목, 외부 시스템의 기술 오류 원문과 가져오기 하위 폴더 이름은 유지합니다.

## 대시보드 사용법

| 버튼 | 동작 |
| --- | --- |
| **변경 사항 미리 보기** | 기록한 버전과 Confluence를 비교해 보고서를 저장합니다. 양쪽 본문 변경, 제목·위치 변경, 첨부파일 추가·수정·삭제를 확인합니다. 페이지 버전이 같아도 첨부파일 변경을 검사합니다. |
| **새 페이지 가져오기** | 연결되지 않은 새 페이지와 첨부파일을 `Imported pages` 아래에 저장하고, 다음 비교에 사용할 버전을 기록합니다. 최초 내려받기에 사용할 수 있습니다. |
| **전체 사본 내려받기** | 모든 페이지의 현재 버전을 `Snapshots` 아래 새 폴더에 저장합니다. 이미 추적하는 페이지도 새 사본으로 받을 수 있습니다. |
| **페이지 목록 불러오기 → 버전 불러오기 → 비교** | 페이지와 두 버전을 선택해 추가·삭제된 Markdown 줄을 확인합니다. |
| **로컬 반영 검토** | 발행한 노트와 연결된 페이지의 이전 발행 버전부터 최신 버전까지 비교합니다. 로컬에서 일치하는 위치를 찾은 변경을 골라 확인 후 반영합니다. |
| **최신 사본 내려받기** | 선택한 페이지의 현재 버전과 첨부파일을 `Snapshots`에 저장합니다. |
| **발행할 문서 검토** | 신규·수정·변경 없음·충돌 목록을 보고 발행 가능한 문서를 선택합니다. 선택하지 않은 문서는 유지합니다. |
| **본문 충돌 해결** | 이전 기준·현재 로컬·현재 Confluence를 비교합니다. 사용할 본문을 고르거나 병합해 편집한 뒤 백업하고 로컬에 저장합니다. 발행은 따로 검토합니다. |
| **작업 이력 열기** | 최근 작업의 결과와 백업을 확인합니다. 백업을 열거나 이후 변경 여부를 검사하고 복원합니다. |

전체 사본과 최신 사본 내려받기는 원본과 이전 사본을 보존하며 추적 기준 버전도 바꾸지 않습니다. 강제로 현재 기준의 내용을 받아보고 싶을 때 이 기능을 사용하세요. 첨부파일은 각 사본의 `Attachments` 폴더에 버전이 포함된 이름으로 저장합니다.

선택한 변경을 로컬에 반영하기 전에는 `Backups` 아래에 원본을 백업합니다. Confluence 버전과 로컬 파일·열린 편집기의 변경 여부를 다시 검사합니다. 위치가 없거나 여러 곳이 일치하는 변경은 선택할 수 없습니다. 이 기능은 발행한 원본 노트와 연결된 페이지에 적용됩니다. 일부 변경만 반영해도 이전 발행 기준은 유지하므로 다음 발행에서 Confluence의 독립 수정 충돌을 계속 알립니다.

## 선택 발행과 이름·폴더 이동

발행이 꺼져 있어도 **발행할 문서 검토** 목록을 읽을 수 있습니다. 문서를 하나씩 고르거나 **발행 가능한 문서 선택**을 사용하세요. 선택한 문서가 아직 발행하지 않은 새 노트를 참조하면 그 노트도 함께 선택해야 합니다. 이미 연결된 링크 대상은 선택하지 않아도 기존 페이지 링크를 유지합니다.

업로드 전 대상, 저장된 본문, 열린 편집기, 첨부파일과 Confluence 버전을 다시 확인합니다. 바뀌었다면 목록을 새로고침해야 합니다. 취소하면 다음 쓰기 요청 전에 멈추며 이미 완료된 변경과 재개에 필요한 상태는 유지합니다.

플러그인이 활성화된 동안 지정한 원본 폴더 안에서 노트나 하위 폴더를 옮기면 페이지 ID를 유지합니다. 다음 선택 발행에서 페이지 제목·상위 위치를 갱신합니다. 필요한 새 대상 폴더를 만들되 기존 폴더는 지우지 않으며, 이전 경로로 돌아오면 소유한 기존 폴더를 재사용할 수 있습니다. 원본 범위 밖으로 옮긴 파일은 발행에서 제외합니다. 이름 변경 충돌은 목록에서 표시하므로 이동을 되돌리거나 빈 경로로 옮겨 해결하세요. 원본 루트 변경이나 비활성화 중 이동은 발행 전에 **연결 관리**에서 확인합니다.

## 연결·복구 관리

대시보드의 **연결 관리** 또는 명령 팔레트의 **연결·복구 관리**를 엽니다. **연결 정보 불러오기**로 현재 범위의 연결됨·미연결·파일 누락·접근 불가·중단된 발행 상태를 확인하고 검색합니다.

- **기존 페이지 재연결**: 미연결 노트와 범위 안의 기존 페이지를 명시적으로 고릅니다. 플러그인을 끈 동안 이동한 노트라면 **이전 누락 연결**도 고릅니다. 신규 연결은 제목·폴더 계층·생성할 본문·참조 첨부파일이 같고 내부 링크 대상이 이미 연결되어 있어야 합니다. 비활성화 중 이동은 기존 로컬 입력과 원격 기준이 유지된 경우만 허용합니다. 다른 변환기나 편집한 내용은 먼저 정리해야 하며 기존 연결·중복 소유는 거절합니다.
- **발행 폴더 매핑 이전**: 설정에서 새 발행 폴더를 지정한 뒤 동일한 Confluence 사이트·루트 폴더의 이전 프로필을 고릅니다. 현재 매핑은 비어 있어야 합니다. 모든 연결 노트·참조 파일·원격 기준이 같아야 하며 미해결 이동·중단된 발행·보존된 이전 폴더 매핑이 있으면 중단합니다. 이전할 경로와 ID를 미리 표시합니다. 기존 프로필은 이전 표시로 남겨 발행을 차단하고 변경 전 정보는 백업에 보존합니다. 페이지 ID와 원격 내용은 유지합니다.
- **완료된 발행 복구**: 결과를 받지 못한 페이지 생성은 기록한 임시 본문이 정확히 일치하는 단일 버전 1 페이지만 연결합니다. 업데이트 응답 유실은 기록한 버전 메시지·본문 해시·위치·첨부파일이 확인될 때 완료 기준을 복구합니다. 완료를 증명하지 못한 업데이트는 **발행할 문서 검토**에서 재개합니다. 결과 불명 폴더 생성, 결과 없음·중복·독립 수정은 표시를 지우지 않고 직접 확인하도록 남깁니다.

**연결 변경 미리 보기 → 연결 변경 적용** 순서로 확인합니다. 적용 직전 다시 검사하며 로컬 Markdown·첨부파일·원격 본문·제목·위치는 변경하지 않습니다. 적용 후 자동 발행을 해제하고 관련 노트는 수동 발행 검토가 필요합니다. 이후 별도로 확인한 발행에서 위치나 내용을 갱신할 수 있습니다.

최근 변경 전 프로필 10개는 개인 `data.json`의 `mappingBackups`에 남습니다. 개인정보인 경로·ID를 포함하므로 공유하지 마세요. 매핑 백업을 자동 복원하는 버튼은 제공하지 않습니다. 저장 실패 시 메모리의 연결 정보를 되돌리고 자동 발행은 해제한 상태로 둡니다.

## 충돌 해결과 복원

**본문 충돌 해결**에서 검토한 현재 Confluence 버전을 새 비교 기준으로 수용합니다. 로컬 본문을 유지하거나 직접 병합한 경우, 다음 수동 발행은 수용한 원격 본문을 선택한 내용으로 갱신할 수 있습니다. 원격 변환 본문을 그대로 선택하면 다음 로컬 수정 전까지 현재 Confluence 본문을 보존합니다. 첨부파일은 Confluence에 유지합니다. 충돌 해결을 거친 문서는 수동 발행을 확인한 뒤 자동 발행을 다시 적용합니다.

플러그인 데이터에는 최근 작업 100개와 백업 기록 100개를 보관하며 화면에는 각각 최근 30개를 표시합니다. 실제 백업은 가져오기 폴더의 `Backups`에 Markdown으로 남기고 자동 삭제하지 않습니다. 이전 버전의 백업 파일도 유지하지만 새 이력 화면의 기록은 없습니다.

복원은 대상 범위, 백업 해시, 현재 노트와 열린 편집기를 확인한 뒤 현재 노트를 다시 백업하고 실행합니다. 백업 이후 노트나 백업 파일을 편집했다면 직접 열어 병합해야 합니다. 로컬 복원은 Confluence 버전이나 수용한 원격 기준을 되돌리지 않습니다.

## 선택 사항인 자동 확인·발행

**자동 변경 확인**은 기본으로 꺼져 있습니다. 켜면 Obsidian 실행 중 원본 폴더의 변경 후와 5분·15분·60분 주기로 확인합니다. 연속 변경은 모아서 처리하고 확인 사이에는 최소 1분을 둡니다. 페이지와 추적 중인 첨부파일의 변경을 알림·작업 이력으로 표시하며 보고서 생성, 가져오기와 삭제를 자동으로 실행하지 않습니다.

**자동 발행**은 별도 설정입니다. **발행 허용**, **자동 변경 확인**을 켜고 표시한 대상에 자동 갱신을 허용해야 합니다. 비교 기준이 있는 기존 연결 페이지의 로컬 수정만 올립니다. 신규 문서, 이동, 미완료 발행, 충돌과 수동 발행을 기다리는 해결 내용은 수동 검토에 남깁니다. 발행·자동 확인을 끄거나 계정·비밀 항목·원본·Confluence 폴더 URL을 바꾸면 자동 발행도 끕니다. 현재 로컬 설치에는 자동 옵션을 켜지 않습니다.

## 기존 설치 업데이트 및 이전 도구에서 전환

플러그인을 비활성화하고 릴리스 파일 3개를 교체한 뒤 다시 활성화합니다. ZIP을 사용한다면 기존 플러그인 폴더 안에 파일을 덮어씁니다. **기존 폴더 전체를 지우지 마세요.** `data.json`에는 페이지 ID와 비교 기준이 있으며, Obsidian의 비밀 저장소에는 인증 토큰이 있습니다. 두 정보를 유지해야 기존 연결을 이어갈 수 있습니다.

다른 발행 도구에서 전환할 때는 페이지 ID, 상위 항목, 제목, 버전을 확인하고 연결 기준을 별도로 이전해야 합니다. 관련 없는 기존 페이지와 제목이 같으면 충돌로 처리합니다. 검증한 이전 기준이 있으면 변환기의 차이로 변경 없는 페이지를 다시 쓰지 않습니다. 이후 원본을 수정하면 이 플러그인의 변환 범위를 적용합니다. 처음에는 발행을 끈 상태에서 연결·미리 보기·사본을 검토하세요.

## 계정 권한과 토큰 범위

대상 Confluence Cloud 폴더에 접근할 수 있는 Atlassian 계정이 필요합니다. 발행 시 해당 계정에 콘텐츠 생성·수정 권한도 있어야 합니다.

- 미리 보기와 가져오기에는 `read:folder:confluence`, `read:hierarchical-content:confluence`, `read:page:confluence`, `read:attachment:confluence`를 사용합니다.
- 발행에는 `write:folder:confluence`, `write:page:confluence`, `write:attachment:confluence`, `read:content-details:confluence`가 추가로 필요합니다.

토큰은 Obsidian SecretStorage에서 가져옵니다. 플러그인 데이터에는 설정, 비밀 항목 이름, 동기화 정보를 저장합니다. 설치용 ZIP에는 개인 설정이나 토큰이 포함되지 않습니다.

## 네트워크와 파일 접근

- 지정한 `*.atlassian.net` 사이트에서 Cloud ID를 확인하고 `api.atlassian.com`을 통해 해당 테넌트에 인증 요청을 보냅니다.
- 미리 보기와 가져오기는 페이지 본문과 첨부파일 정보를 읽습니다. 첨부파일은 지정한 버전을 요청한 뒤 `api.media.atlassian.com`의 서명된 주소에서 내려받으며 계정 토큰을 전달하지 않습니다.
- 수동 발행은 사전 검사와 사용자 확인 후 선택한 노트, 폴더·페이지 이름과 참조된 첨부파일을 보냅니다. 자동 발행은 별도 허용 후 조건을 충족하는 기존 연결 문서의 변경을 보냅니다. 온라인 이미지는 링크로 발행하며 플러그인이 외부 이미지 서버에서 가져오지 않습니다.
- 분석·사용 통계 전송 기능은 없습니다. 보관함은 Obsidian API로 접근합니다. 파일 목록은 지정한 원본 폴더의 하위 항목만 순회하며 숨김 원본 경로와 숨김 첨부 대상은 제외합니다. 사용자가 선택 반영·충돌 해결·백업 복원을 확인한 경우에만 기존 노트를 수정하며 로컬 파일이나 Confluence 페이지를 자동으로 삭제하지 않습니다.
- 하나의 Confluence 폴더에는 발행 담당 설치본 하나를 지정하고, 다른 설치본에서는 미리 보기와 가져오기를 사용하는 것을 권장합니다.

## 문제 해결

| 상황 | 확인할 내용 |
| --- | --- |
| 선택할 수 있는 문서가 없음 | **변경 없음**과 **충돌** 행은 선택할 수 없습니다. 열린 편집기를 저장하고 검토 목록을 새로고침한 뒤 행의 설명을 확인하세요. 업로드에는 **발행 허용**도 필요합니다. |
| 다른 노트도 선택하라는 안내 | 선택한 문서가 참조하는 미발행 노트를 함께 선택하세요. 이미 연결된 링크 대상은 선택하지 않아도 됩니다. |
| 원격 페이지나 첨부파일이 변경됨 | 목록을 새로고침하고 현재 버전을 확인하세요. 연결된 본문의 충돌은 **본문 충돌 해결**을 사용합니다. 독립적인 제목·상위 위치 변경과 미완료 발행은 먼저 정리해야 본문 해결을 사용할 수 있습니다. |
| 발행 취소·연결 중단 | 완료된 변경은 유지됩니다. 새로고침 후 연결과 버전을 확인할 수 있는 문서를 다시 선택하세요. 생성 결과를 알 수 없다면 대상 페이지를 확인하고 `data.json`을 보존하세요. 연결 기록을 삭제하면 중복이 생길 수 있습니다. **연결 관리**에서 완료를 증명할 수 있는 작업을 복구할 수 있습니다. 결과 불명은 차단 상태를 유지합니다. |
| 이름 변경에 연결 충돌이 발생함 | 이동을 되돌리거나 비어 있는 경로로 옮긴 뒤 새로고침하세요. 비활성화 중 이동과 원본 루트 변경은 기준이 유지된 경우 **연결 관리**에서 처리합니다. |
| 연결 오류 HTTP 401·403 | 계정 이메일, 선택한 토큰의 유효성·범위와 대상 폴더 접근 권한을 확인하세요. 토큰을 이슈나 화면 캡처에 넣지 마세요. |
| 첨부파일 전송 실패 | 현재 제한은 파일당 25 MiB입니다. 허용하지 않은 호스트나 크기가 맞지 않는 전송은 차단합니다. 원본을 보존하고 오류를 확인하세요. |
| 자동 발행이 동작하지 않음 | Obsidian 실행 중 **발행 허용**, **자동 변경 확인**, 별도 확인한 **자동 발행**이 켜져 있어야 합니다. 신규·이동·충돌·미완료 작업은 수동 검토합니다. |
| Mermaid가 코드로 보임 | 0.6.0은 Mermaid 소스를 코드 매크로에 발행합니다. 로컬 이미지 렌더링은 로드맵 항목입니다. |

## 지원 범위와 한계

- 제목, 기본 강조, 목록, Markdown 표, 코드 블록, 지정한 원본 폴더 내부 링크와 참조된 첨부파일을 발행합니다. 첨부파일은 개당 최대 25 MiB입니다.
- Mermaid는 Confluence 코드 매크로에 소스로 발행합니다. Confluence에서 자동으로 다이어그램으로 그리는 기능은 제공하지 않습니다. Markdown 확장 문법과 Confluence의 모든 편집 기능을 완전히 변환하지는 못합니다.
- 가져오기는 별도 폴더에 새 페이지 본문과 첨부파일을 저장하고 크기를 확인합니다. 버전 비교와 선택 반영은 변환된 본문 텍스트를 대상으로 하며 첨부파일 변경은 보고서에 따로 표시합니다.
- macOS의 Obsidian 1.14.5에서 0.6.0 설치, 비밀 저장소 인증과 한국어 관리 화면의 기존 연결 85개를 읽기 전용으로 확인했습니다. 이전 0.5.0의 발행 검토·이력 검증 근거도 유지합니다. 선택 발행·충돌 해결·복원·연결 관리 동작은 두 언어의 합성 시험으로 검증했으며 이전 네이티브 합성 첨부파일 가져오기 근거도 유지합니다. 추가로 macOS·Windows·Linux의 실제 Obsidian 1.14.5에서 합성 자료로 UI/API 로딩, SecretStorage 읽기·쓰기, 선택 반영·백업 복원, 바이너리 가져오기, 이동 이벤트와 플러그인 재로딩을 검증했습니다. 정확한 CI 근거는 [시험 안내](testing/README.ko.md)에 있습니다. Windows는 공식 배포 파일을 추출해 실행했으며 설치 프로그램 UI·OS 키체인 보장·Windows/Linux의 실제 Atlassian 인증은 이번 시험 범위에 포함하지 않습니다. 모바일은 지원하지 않습니다.

## 개발 및 공식 등록

읽기 전용 검토는 페이지 메타정보를 묶어 조회하고 확인 한 번 안에서 페이지·첨부 응답을 재사용합니다. 다음 검토와 쓰기 전 검사는 새 상태를 조회합니다. 연결당 REST 요청은 최대 4개이며 GET 재시도는 서버 대기 시간을 존중하고 60초 대기 한도를 적용합니다. POST·PUT·응답 불명 쓰기는 자동 재전송하지 않습니다. 세부 범위와 합성 측정은 [성능 비교 안내](testing/PERFORMANCE.md)를 참고하세요.

`npm ci --ignore-scripts --offline --no-audit --no-fund`로 의존성이 없는 lockfile을 확인한 뒤 `npm run build`로 `main.js`를 생성하고 `npm test`로 빌드와 시험을 실행합니다. Node.js는 개발자에게만 필요합니다.

공개 영문·한글 Chromium 시험과 임시 Obsidian 보관함의 실제 앱 시험은 [UI·네이티브 시험 안내](testing/README.ko.md)에 정리했습니다. 개발 시험용 의존성과 lockfile은 `testing/`에 분리하며 플러그인 배포 파일에 포함하지 않습니다.

릴리스 태그는 `manifest.json`의 버전과 같고 `v` 접두사를 붙이지 않습니다. `versions.json`은 Obsidian 최소 버전을 기록합니다. 릴리스에는 `main.js`, `manifest.json`, `styles.css`를 개별 파일로 올리며, 수동 설치용 ZIP과 검증용 `SHA256SUMS.txt`를 함께 제공합니다. ZIP에는 플러그인 폴더와 설치 파일, 두 언어의 안내 문서와 `LICENSE`를 넣습니다.

공식 제출에는 사용 안내, `LICENSE`, manifest와 일치하는 GitHub 릴리스가 필요하며 [Obsidian Community](https://community.obsidian.md/)에서 진행합니다. macOS·Windows·Linux의 네이티브 합성 시험을 완료했으며 세부 범위와 한계는 시험 안내에서 확인할 수 있습니다. 공개 플러그인 ID의 사용 가능 여부도 제출 전에 확인합니다. [공식 등록 안내](https://docs.obsidian.md/plugins/releasing/submit-plugin)를 참고하세요. 변경 이력과 검증 범위는 [CHANGELOG.md](CHANGELOG.md)에 기록합니다.

CI는 오프라인 `npm ci`로 루트 lockfile을 확인하고 Linux·macOS·Windows에서 Node 시험 78개와 영문·한글 Chromium 시험을 실행합니다. 생성한 `main.js`와 커밋한 파일의 일치 및 배포 정보·패키징도 검사합니다. 별도 작업에서는 SHA256을 고정한 공식 Obsidian을 내려받아 Windows·Linux의 임시 합성 보관함에서 실행합니다. 분리된 시험용 의존성 설치에만 npm 레지스트리 접근이 필요하며 모든 Confluence 응답은 합성입니다. 유지관리자는 Node.js 26과 패키징용 Python 3을 사용하며 사용자는 둘 다 설치할 필요가 없습니다.

새 버전은 manifest·package·lockfile·versions·변경 이력과 설치 링크를 갱신하고 빌드·커밋한 뒤 정확한 `x.y.z` 태그를 푸시합니다. 릴리스 워크플로가 CI를 기다린 뒤 실행 파일 3개·두 언어의 안내·변경 이력·MIT 라이선스만 패키징하고 배포 파일에 빌드 출처 증명을 붙입니다. 초안을 만든 뒤 내려받은 파일·ZIP 허용 목록·서명 워크플로·원본 태그·커밋을 검증하고 공개합니다. 기존 릴리스 파일은 덮어쓰지 않습니다. 실패한 초안은 동일 커밋과 기존 파일이 모두 일치할 때 누락 파일만 추가하고 출처를 재검증해 재개합니다. 변경된 태그나 일치하지 않는 초안은 거절합니다. 일반 CI와 PR은 읽기 전용 권한이며 태그 릴리스 작업만 배포·출처 증명 권한을 사용합니다.

로컬 패키징 검사는 `python3 -m unittest discover -s tools -p 'test_*.py' -v`로 실행합니다. `python3 tools/release.py --tag 0.7.0 --output /tmp/confluence-folder-sync-0.7.0`로 새 패키지를 만듭니다. 같은 릴리스에서 배포 파일을 내려받고 체크섬을 확인한 뒤 `gh attestation verify main.js --repo hyun-seung/confluence-folder-sync --signer-workflow hyun-seung/confluence-folder-sync/.github/workflows/release.yml --source-ref refs/tags/0.7.0`로 출처를 확인합니다. 다른 파일도 각각 검사하며 정확한 커밋까지 고정하려면 `--source-digest <태그의 전체 커밋>`을 추가합니다.
